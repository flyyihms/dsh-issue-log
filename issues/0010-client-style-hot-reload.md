# 0010 · 客户端插件热重载后样式丢失，新类名渲染成裸元素

| 项 | 内容 |
|---|---|
| 现象分类 | UI / 插件 / 热重载 |
| 平台 | Windows 11 x64 |
| DSH | 0.2.1-rc.3 |
| 严重程度 | 低（纯视觉，但会让人误以为"设计丑"） |
| 状态 | 规避方案（每次覆盖 style 内容） |
| 关键词 | 客户端插件、style 注入、热重载、HMR |

## 症状

重做插件里分段控件的样式后刷新页面，控件却变成**没有容器背景、没有内边距的裸按钮**，文字挤在一起，看起来像"设计退化成最丑版本"。

与此同时，同一份 CSS 里的其它规则（抽屉、输入框、列表）都正常生效。

## 环境

- DSH 0.2.1-rc.3 桌面版，客户端插件（`dsh.client`）
- 样式通过 `document.createElement("style")` 注入 `<head>`
- 迭代方式：改 `lib/client.js` → 页面刷新/热应用

## 排查思路

1. 确认新 DOM 类名（如 `.dshn-seg`）是否出现在元素上 → 出现。
2. 确认样式表里有没有该选择器 → 用 DevTools 查 `<style id="…">` 内容。
3. 对比"元素类名"与"样式表内容"是否来自同一个版本。

## 被排除的假设

| 假设 | 做法 | 结果 | 结论 |
|---|---|---|---|
| CSS 语法错误导致整表失效 | 检查其它规则 | 其它规则生效 | 排除 |
| 类名写错 | 对比 DOM 与 CSS | 一致 | 排除 |
| 样式优先级被覆盖 | 查匹配规则 | 查不到该规则 | 排除 |
| 元素没渲染 | 看 DOM 树 | 元素存在 | 排除 |

## 转折点

DevTools 里打开自定义 `<style>`，里面是**上一版**的 CSS（只有旧类名 `.dshn-switch`），而 DOM 用的是新类名 `.dshn-seg`——两者版本不一致，于是新元素没有任何规则命中。

## 根因

**已验证**：样式注入函数里有"已存在就 return"的幂等保护：

```js
if (document.getElementById(STYLE_ID)) return;   // ← 问题所在
```

热重载时旧 `<style>` 仍在 DOM 中，函数直接返回，新 CSS 从未写入，导致新类名无样式。

## 修复

保留幂等，但**每次都覆盖内容**：

```js
let style = document.getElementById(STYLE_ID);
if (!style) { style = document.createElement("style"); style.id = STYLE_ID; document.head.appendChild(style); }
if (style.textContent !== CSS) style.textContent = CSS;
```

## 验证

| 检查 | 修复前 | 修复后 |
|---|---|---|
| 刷新后分段控件外观 | 裸按钮（无背景/内边距） | 正常分段控件 |
| `<style>` 内容版本 | 旧版 | 与代码一致 |
| 首次加载 | 正常 | 正常 |

## 教训

- 客户端插件注入样式时，**不要用"元素已存在"作为"样式已最新"的判断依据**；热重载环境下元素会存活，内容不会自动更新。
- 遇到"只有新加的元素丑、老的都正常"，先怀疑样式表版本不一致，而不是设计参数。
- 每轮 UI 迭代后让用户硬刷新（Ctrl+R）或完全重启，能排除一类缓存型假象。

## 复现要点（脱敏）

1. 客户端插件用 "已存在就 return" 的方式注入 CSS。
2. 修改 CSS 中的类名/规则后触发重载（不刷新整页）。
3. 新元素出现但无样式；DevTools 中 `<style>` 仍是旧内容。
